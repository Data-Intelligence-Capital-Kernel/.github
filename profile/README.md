## Overview

**DICK Research** is a technical collective focused on turning engineering skill into financial leverage.

Our background spans software development, trading, game development, systems tooling, automation, data analysis, and experimental research. We build tools and infrastructure at the intersection of programming, markets, data intelligence, and applied systems research.

We are here to build durable systems, learn quickly, and compound useful knowledge into useful capital.

## What D.I.C.K. Means

### Data

### Intelligence

We build systems that help us observe, think, decide, and adapt.

This includes research tooling, automation, models, agents, analytics, simulations, and decision-support systems.

### Capital

We are interested in markets, trading, allocation, ownership, and financial outcomes.

Code is not just an art form. Code is leverage.

### Kernel

Reliable primitives, repeatable processes, reusable tools, and clean abstractions beat fragile one-off scripts.

## Core Principles

### Build systems, not vibes

A good idea should survive contact with data, tests, and time.

We prefer working software over impressive theory, but we respect theory when it earns its keep.

### Measure before believing

Backtests, logs, benchmarks, paper trading, postmortems, and real-world results matter.

We try not to confuse confidence with correctness.

### Automate the boring parts

Humans should focus on judgment, design, research, and strategy.

Machines should handle repetition, collection, formatting, scanning, alerting, and execution where appropriate.

### Compound knowledge

Every project should make the next project easier.

Every tool should teach us something.

Every failure should become documentation, infrastructure, or a better constraint.

### Stay dangerous, stay disciplined

We like ambitious ideas, weird experiments, and asymmetric opportunities.

We also like version control, risk limits, reproducibility, and not blowing ourselves up.

## Repository Philosophy

We prefer repositories that are:

- Purposeful
- Documented
- Testable
- Reproducible
- Composable
- Honest about limitations

A repository does not need to be huge to be valuable.

A small tool that solves a real problem is better than a sprawling system nobody wants to maintain.
